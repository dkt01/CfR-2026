## Why two regions have no bounds

`narrow_region` and `wide_open_region` are named stops in
`jetson/README.md`'s course tour, but `generate_obstacle_course.py` never
draws a rectangle for either one -- they're not a poured feature like the
gravel pit or the bank, they're a description of a stretch of ordinary
32 in (`LANE_WIDTH`) lane. `wide_open_region` is the same "wide area" that
`obstacle_randomizer_node`'s gap-bale wall separates from the bucket
section (see `jetson/README.md`'s "bucket section's entrance" note, and the
`generate_obstacle_course.py` `GAP_BALES`/`GAP_WALL_BOUNDS` constants).

If you need to reason about a point that falls in one of these two, say so
rather than presenting a fabricated box as authoritative: "this point is
between the tunnel and the gravel pit, in the connecting lane" is accurate;
inventing coordinates for `narrow_region` is not.

## Display boxes vs. actual matching

`helical_ramp` and `hoops` have real constants, but the box shown in the
table above is not the shape `near`/`classify` actually test against --
it's there so `list`/`show` have a quick number to print:

- `helical_ramp` is really an annulus (inner/outer radius) swept through
  270 degrees; `in_helix()` checks the true radius range and angle sweep,
  which correctly excludes the hollow centre and the 90 degree wedge the
  tunnel sits in.
- `hoops` is really three separate line segments; `near_hoop_line()` checks
  perpendicular distance to the nearest one (within `HOOP_LINE_TOLERANCE`,
  half the hoop's base width plus a little slack), not "anywhere in the box
  around all three."

This mattered in practice: an earlier version used the bounding boxes for
matching too, which mislabeled a point sitting exactly on a hoop's nominal
line as "no match" (the fixed-x line sat exactly on the box's edge, so a
float-rounded coordinate landed just outside it) and blurred the helix
and tunnel together near where their boxes overlap.
